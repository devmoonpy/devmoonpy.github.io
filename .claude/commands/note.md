description: 메모를 지식베이스(knowledge-site/content/)에 정리해서 저장한다
---

사용자가 입력한 내용을 `knowledge-site/content/`에 마크다운 노트로 정리해서 저장한다.

입력: $ARGUMENTS

이 저장소(`devmoonpy.github.io`)는 **공개 저장소**다. 여기 커밋되는 순간 인터넷에 공개되고 git 히스토리에 영구히 남는다. 별도의 비공개 초안 저장소는 두지 않기로 했으므로, 이 명령이 사실상 유일한 검토 시점이다.

## 절차

1. **민감정보 확인 먼저.** 입력 내용에 다음이 보이면 그대로 저장하지 말고 사용자에게 확인한다:
   - 실제 서버 주소, 사설/공인 IP, 접속 정보
   - 인증정보, API 키, 토큰, 비밀번호
   - 회사 내부자료, 특정할 수 있는 개인 기록
   - 아직 공개해도 안전한지 불확실한 보안 실습 내용
   확실하지 않으면 "이거 공개 저장소에 저장해도 되나요?"라고 물어본다. 애매하면 안전한 쪽(묻기)으로 기운다.

2. **분류.** 아래 중 어디에 넣을지 정한다. 내용상 명확하면 바로 정하고, 애매하면 짧게 물어본다.
   - `projects/` — 진행 중이거나 끝낸 프로젝트 기록
   - `security/` — 취약점 분석, CTF, 레드팀 관점 웹 공격 노트
   - `server-network/` — 서버·네트워크 구성, 인프라 학습 (개념 위주, 실제 구성정보 금지)
   - `decisions/` — 기술적 결정과 그 이유
   - 어디에도 안 맞으면 `knowledge-site/content/` 루트에 바로 저장해도 된다.

3. **관련 노트 연결.** `knowledge-site/content/` 안에서 Grep으로 관련 있어 보이는 제목/태그를 찾아, 있으면 본문에 `[[slug|표시할 텍스트]]` 형태의 위키링크로 자연스럽게 연결한다. 억지로 연결하지 않는다.

4. **파일 작성.** `knowledge-site/content/<섹션>/<슬러그>.md` 로 저장한다(슬러그는 제목에서 kebab-case로). frontmatter는 최소한으로:
   ```yaml
   ---
   title: <제목>
   tags: [<추론한 태그 몇 개>]
   ---
   ```
   아직 다듬는 중이라 당장 사이트에 노출하고 싶지 않으면 `draft: true`를 frontmatter에 추가한다 — 빌드에서 자동으로 빠진다. 단, **draft여도 커밋하면 이미 공개 저장소 git 히스토리에는 남는다.** 진짜 비밀이면 draft가 아니라 아예 저장하지 않아야 한다(1번 확인 사항).

5. **저장 후 안내.** 파일을 저장했다는 것과 경로를 짧게 알려준다. 커밋/푸시는 하지 않는다 — 그건 `/publish`가 할 일이다.
